- Sidecar path resolution WITHOUT the shell plugin (src-tauri/src/sidecar.rs):
  checks next-to-exe (production bundle) then src-tauri/binaries/<name>-<triple>
  (dev). Triple baked in via build.rs (cargo:rustc-env=TARGET_TRIPLE from TARGET).
  Reason: the shell plugin inserts \n between stdout chunks (#3090) and would
  corrupt the progress stream — CLAUDE.md gotcha. We spawn std::process::Command.
- src-tauri/src/url_import.rs — download_url + cancel_download commands:
    * Spawns yt-dlp via std::process::Command (CREATE_NO_WINDOW on Windows),
      downloads to a unique OS temp dir (captionsmith-dl-<pid>-<n>/source.%(ext)s),
      returns the produced file path as the local source (read in place, per the
      zero-import constraint; temp file, deleted on cancel/failure).
    * Format "best[ext=mp4]/best" — a single pre-muxed stream, so the download
      step does NOT depend on ffmpeg merging (that comes in Step 4).
    * Streams progress: reads BOTH stdout and stderr, parses "[download] NN.N%"
      via parse_percent, emits "download-progress" { percent, line }.
    * Cancellable: AtomicBool cancel flag + child stashed in managed
      DownloadState; cancel_download flips the flag and kills the child. Mirrors
      ClipSmith's cancel race (adapted to std threads since std::process is sync).
- Frontend (src/App.tsx + app.css): URL bar under the dropzone (Enter or Import),
  a downloading panel with a gradient progress bar (indeterminate until the first
  percent), the live yt-dlp status line, and a Cancel button. Esc cancels an
  in-flight import. On success the temp file loads into the same player as a
  local file. "cancelled" is handled quietly (not shown as an error).

--- Step 9: Burn-in export (libx264 + ass filter) ----------------------------
DONE (code complete + CLI-validated end-to-end; needs live-window test).

    * probe_video (ffprobe) reads the video's WxH + duration; the ASS PlayRes is
      set to the exact video dimensions so positions/sizes are precise.

    * Runs: ffmpeg -i <src> -vf "ass=captions.ass:fontsdir=fonts" -c:v libx264

      tauri.conf resources; copied into <work>/fonts/ and referenced with

      System fonts (Arial/Impact/Georgia) still resolve via the platform provider
      (DirectWrite on Windows).
    * time= parsed against the probed duration -> "burn-progress" { percent }.
    * Cancellable via BurnState's Cancellation (kills ffmpeg); on cancel/error it

--- Roadmap item 2: SRT / VTT import (bring-your-own transcript) --------------

Goal: load an existing .srt/.vtt, turn its cues into the same editable Segment

Rust (src-tauri/src/subimport.rs, registered in lib.rs):
- import_subtitles(path) command: gates on .srt/.vtt extension, reads the file,
  parses to Vec<Segment>, errors clearly on wrong ext / unreadable / no cues.
- ONE block parser (parse_subtitles) handles BOTH formats — their cue shape is
  identical (a "start --> end" line + text lines). It absorbs the differences:
    * strips a UTF-8 BOM, normalizes \r\n and \r to \n
    * splits on blank lines; skips any block without "-->" (WEBVTT header,
      NOTE/STYLE/REGION, lone index/id lines)
    * parse_timestamp accepts HH:MM:SS.mmm, MM:SS.mmm, SRT comma ms (,mmm), and
      ignores trailing VTT cue settings ("... line:90% position:50%")
    * strip_tags removes inline VTT tags (<v ...>, <c>, <b>, <00:00:01.000>)
    * a cue identifier / SRT index line before the timing is dropped; text lines
      after it are tag-stripped, blank-filtered, joined and whitespace-collapsed
      into one clean line the styler re-wraps
    * words = None (subtitle files carry no word timings), so word-highlight
      falls back to plain wrapping — already handled in both the ASS builder and
      the HTML overlay (verified: overlay's useWords() guards on words.length>0)
    * sorts by start (the transcript editor assumes a start-ordered list)
